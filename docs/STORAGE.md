# แหล่งข้อมูลพื้นที่เก็บข้อมูล

เมื่อกำหนด `storage_api: "swizzin"` ทั้ง qBittorrent และ rTorrent ใช้ตัวอ่าน
`storage_telemetry.py` ร่วมกัน โดยเลือกข้อมูลโควตาบัญชีจาก panel ก่อน
และใช้ดิสก์ตาม mount เป็นแหล่งสำรองเมื่อไม่มีโควตา

Swizzin ใช้ได้ทั้งบริการ shared seedbox และเซิร์ฟเวอร์ที่ผู้ใช้ติดตั้งเอง
เช่น dediserver การเลือก quota/mount จึงตรวจจากข้อมูลที่ panel ส่งกลับจริง
โดยไม่ผูกกับชื่อผู้ให้บริการหรือ hostname: หากเปิด quota จะใช้ข้อมูลบัญชี
หากไม่ได้ติดตั้ง quota จะใช้ mount ตามที่ตั้งค่าไว้ ทั้งสองแบบใช้กติกาเดียวกัน

| ข้อมูล quota | ข้อมูล mount | ผลลัพธ์ |
|---|---|---|
| มีและถูกต้อง | มี | ใช้ quota โดยไม่เรียก API ของ mount |
| มีและถูกต้อง | ไม่มี | ใช้ quota |
| ไม่มี | มีและถูกต้อง | ใช้ mount ที่กำหนด |
| ไม่มี | ไม่มีหรืออ่านไม่ได้ | หยุดรับงานจากข้อมูลพื้นที่รอบนั้น โดยตั้งพื้นที่ใช้ได้เป็น 0 |

quota เหลือ `0` หมายถึงโควตาหมด ไม่ใช่ไม่มีโควตา ส่วนกรณีไม่มี quota ได้แก่
endpoint `/stats/quota` ตอบ HTTP `404`, `405`, `501` หรือ JSON object ที่ไม่มี
`quota`/มี `quota: null` และคำตอบ HTTP `200` ที่มีเฉพาะข้อความ
`Quota not installed` ใน `text/html` หรือ `text/plain` ตาม
[โค้ดต้นฉบับ Swizzin panel](https://github.com/liaralabs/swizzin_dashboard/blob/master/swizzin.py#L373-L380)
ซึ่งตรวจการติดตั้ง quota จาก `/install/.quota.lock`

timeout, HTTP `401`/`403`/`5xx` อื่น ๆ,
หน้า HTML, JSON เสีย หรือค่าโควตาที่ไม่ถูกต้องจะเป็นข้อผิดพลาด และไม่สลับไปใช้ mount
เพื่อหลีกเลี่ยงการข้ามข้อจำกัดบัญชีโดยใช้พื้นที่ดิสก์ทั้งเครื่อง

## การตั้งค่าใน NODES

เพิ่มค่าเหล่านี้ใน node เดิมได้ทั้ง `type: "qbit"` และ `type: "rtorrent"`:

```json
{
  "storage_api": "swizzin",
  "storage_mount": "/",
  "storage_safety_buffer_gb": 2
}
```

`storage_mount` เป็นตัวเลือก ค่าเริ่มต้นคือ `/` และใช้เฉพาะตอน fallback
หากข้อมูลดิสก์อยู่ที่ `/home` ต้องกำหนด `"storage_mount": "/home"` ให้ตรงกับ
key ใน `/stats/disk` ระบบจะไม่เลือก mount อื่นแทนเมื่อหา mount ที่กำหนดไม่พบ
`storage_safety_buffer_gb` ใช้หน่วย GiB และค่าเริ่มต้นเดิมคือ 15 GiB

พื้นที่ที่ใช้ตัดสินใจรับงานคำนวณดังนี้:

```text
max(0, min(พื้นที่เหลือจาก quota หรือ mount ที่เลือก,
           พื้นที่ว่างจริงจาก torrent client) − พื้นที่สำรอง)
```

rTorrent อ่านพื้นที่จริงด้วย `d.free_diskspace` ของงานที่มีอยู่ โดยค่าตอบกลับเป็น **ไบต์**
รองรับตัวเลข XML-RPC `i8` และเลือกค่าต่ำสุดเมื่อมีหลายตำแหน่ง ไม่เรียกคำสั่ง
`network.disk_free_4gb` ซึ่ง rTorrent มาตรฐานไม่มี และไม่คูณค่าตอบกลับด้วย 4096
หาก client ยังไม่มีงานให้ตรวจ path หรือ RPC ระบุชัดว่าไม่รองรับ `d.free_diskspace`
จะแสดง `FREE(RT): N/A` และใช้พื้นที่ quota/mount ที่ยืนยันจาก Swizzin ได้เพียงแหล่งเดียวก่อนหัก buffer
หากไม่มีแหล่ง Swizzin ให้ยืนยันด้วย จะถือว่าพื้นที่ยังไม่ทราบและหยุดรับงาน
ส่วน timeout, authentication failure, RPC fault อื่น หรือข้อมูลผิดรูปแบบยังถือเป็นความล้มเหลว
จะไม่เปลี่ยนไปใช้ค่าที่มากกว่าเพื่อรับงานต่อ และ Cleaner จะไม่เริ่มคืนพื้นที่จาก refresh ที่ล้มเหลว

ค่า native ที่อ่านได้จริงเป็น `0` ยังคงเป็นเพดานพื้นที่เต็ม ไม่เหมือน `N/A`
rTorrent แสดง `Buffer` แยกจากค่าพื้นที่ดิบ เช่น quota เหลือ `5.76 GiB`, ดิสก์เหลือ `11.67 GiB`
แต่ buffer ตั้งไว้ `15 GiB` จะได้ `Safe: 0.00 GiB` แม้ API ทำงานถูกต้อง
การลบคีย์ buffer ไม่ได้แปลว่าเป็นศูนย์ เพราะยังใช้ค่าจาก storage หรือค่าเริ่มต้น 15 GiB
ถ้าต้องการไม่หัก buffer ต้องกำหนดค่า `0` ชัดเจน การแก้ตัวอ่านพื้นที่ไม่เปลี่ยนคอนฟิกนี้ให้อัตโนมัติ

quota ของ panel ใช้ข้อมูลบัญชีจริง รวมไฟล์ที่ client อื่นใช้และไฟล์ที่ไม่ได้อยู่ใน
รายการ torrent จึงไม่ประมาณ quota จากผลรวมขนาด torrent เมื่อเปิดตัวอ่าน Swizzin
โดยเฉพาะงาน Cross-Seed ที่หลาย hash ใช้ไฟล์ชุดเดียวกัน

สถานะแสดง `Source: quota` หรือ `Source: mount` พร้อมพื้นที่ก่อนและหลังหักสำรอง
ฟิลด์ `storage_total_gb`, `storage_used_gb`, `storage_free_gb` เป็นค่าดิบของแหล่ง
ที่เลือก ส่วน `free_gb` เป็นค่าที่ปรับแล้ว และตัวคำนวณจำนวนงานใช้ capacity ของ
แหล่งเดียวกัน เมื่อ fallback จะล้าง `quota_*` และเมื่อ refresh ล้มเหลวจะล้าง
ข้อมูล telemetry เดิมทั้งหมด

OnlyOneSeedbox ยังคงใช้ API quota และขั้นตอน SSO ของผู้ให้บริการเดิม ไม่เรียก
endpoint ของ Swizzin แทน ส่วน node ที่ไม่ได้กำหนด `storage_api` ใช้ตัวอ่านเดิม
การเปลี่ยนนี้ไม่แก้สวิตช์เปิดใช้งาน node, Cleaner หรือการคืนพื้นที่อัตโนมัติ
